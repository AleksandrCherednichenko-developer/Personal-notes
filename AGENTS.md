# Правила разработки

Перед выполнением задачи:

1. Прочитать `README.md` и только релевантный текущей задаче код.
2. Не менять файлы вне scope текущей задачи.
3. Не устанавливать зависимости, не указанные в текущей спецификации.
4. Не использовать UI-, undo/redo- и automatic persistence-библиотеки.
5. Для бизнес-логики сначала писать тесты и убедиться, что они падают по ожидаемой причине.
6. После реализации выполнить команды из раздела «Проверки» в `README.md`.
7. Не инициализировать Git и не создавать commits: пользователь управляет репозиторием самостоятельно.

## Решения проекта

- Nuxt 4 SPA, Composition API, TypeScript strict и Pinia.
- Persistence и история изменений реализуются вручную.
- Компоненты не обращаются к `localStorage` напрямую.
- Абстракции добавляются только при наличии понятной обязанности и реального потребителя.
- Публичные контракты меняются только в рамках текущей задачи.
